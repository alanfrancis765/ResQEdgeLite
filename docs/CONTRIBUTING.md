# Working Rules

- `master` must remain buildable. Test changes before merging.
- Use short-lived feature branches for significant changes.
- Use descriptive branch names, such as `feat/sos-packet` or `feat/nearby-mesh`.
- Commit small, logical changes with clear messages.
- Build and test before merging into `master`.
- Keep generated build files and local configuration out of Git.
- Changes to `docs/packet-spec-v1.md` must be reviewed against the agreed v1 protocol.
- Once the hackathon demo is near, prioritize bug fixes over new features.
